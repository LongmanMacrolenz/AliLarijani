# 로드맵 — 프로토타입에서 실서비스로

지금 저장소는 "화면 + 점수 규칙"까지입니다. 실제 계정을 분석하려면 아래가 필요합니다.
**플랫폼 정책·법령·API 조건은 자주 바뀌므로, 각 항목은 개발 착수 시점에 원문을 다시 확인하세요.**

## 1. 먼저 결정할 것: "누구의 글을 평가하는가"

| 방식 | 장점 | 위험 |
|---|---|---|
| **본인 연동 (OAuth 동의)** — 인증서를 사려는 사람이 직접 계정을 연결 | 공식 API로 합법적 수집, 개인정보·약관 리스크 최소, 인증서의 수요자가 곧 고객 | 점수가 낮은 사람은 연동하지 않는 *선택 편향* → 인증서의 의미는 "자발적 공개" |
| **제3자/공인 계정 평가** (연동 없이 공개 게시물 분석) | 뉴스성·유입력이 큼 | 플랫폼 약관(스크래핑 금지), 개인정보보호법, **명예훼손**(한국 형법은 사실 적시 명예훼손도 처벌 대상) 등 법적 리스크가 큼 → 사전 법률 검토 필수 |

권고: **1단계는 본인 연동만**. 프로토타입의 동의 체크박스·문구도 이 전제로 만들어져 있습니다.

## 2. 데이터 수집

- 각 플랫폼의 **공식 API + 계정 소유자 OAuth**만 사용 (Threads, Instagram, X, Facebook). 스크래핑은 약관 위반이며 차단·법적 분쟁 위험이 큽니다.
- 플랫폼마다 접근 가능한 범위(본인 게시물만 / 비즈니스·크리에이터 계정 한정 / 앱 심사 필요 / 유료 티어)가 다릅니다. **"모든 글"을 가져오지 못하는 플랫폼이 있을 수 있어** 인증서에 "평가에 사용된 소스와 기간"을 명시해야 합니다.
- 게시물 원문은 평가 후 최소 기간만 보관하고, 동의 철회·삭제 요청 경로를 둡니다 (개인정보처리방침).

## 3. 분석 파이프라인

```
게시물 수집 ─▶ 발언 추출 ─▶ 근거 검색 ─▶ 판정 ─▶ 시세 매칭 ─▶ 점수 엔진 ─▶ 발급
 (OAuth)      (분류·추출)   (공식 자료)   (근거 인용)  (전망 발언)  (engine.js)    (서명)
```

1. **발언 추출** — LLM + 구조화 출력으로 게시물에서 (a) 검증 가능한 사실 주장, (b) 방향·대상·기간이 있는 전망만 추출하고 주제(법안/판결/경제/정치)를 분류. 의견·농담은 버립니다. 기간 표현("3개월 안에", "연내")은 `horizonDays`로 정규화하고, **기간이 없으면 `null`**(→ 현재 기준)로 둡니다.
2. **근거 검색** — 일반 웹 검색이 아니라 **공식 자료만** 색인합니다. 예: 한국은행 ECOS, 통계청 KOSIS, 열린국회정보(의안), 국가법령정보, 대법원/헌법재판소 판결·결정문, 한국거래소 시세 등 각 기관의 공개 API/데이터. (제공 형태와 이용 조건은 기관별로 확인)
3. **판정** — 모델은 검색된 공식 문서를 *인용하면서만* 판정할 수 있게 제한하고, 근거 문서가 없으면 "검증 불가"로 둡니다. 신뢰도가 낮거나 점수에 크게 영향을 주는 판정(법안·판결)은 **사람이 검수**합니다.
4. **시세 매칭** — 전망 발언의 대상(지수/환율/부동산지수)을 자산 코드로 매핑하고, 발언 시점 이후 누적 등락 시계열을 만듭니다.
5. **점수 엔진** — `assets/js/engine.js`를 그대로 서버(Node)로 옮기거나 같은 규칙으로 재구현하고, `tests/`를 회귀 테스트로 씁니다. 인증서에는 **엔진 버전**을 기록합니다.
6. **발급** — 서버가 발급번호를 생성·저장하고 서명합니다. 공개 **검증 페이지**(발급번호 → 점수·등급·기준일·엔진 버전·유효 여부)를 두어야 인증서가 이미지 이상의 의미를 갖습니다.

## 4. 서비스 요소

- **결제·권한**: 결제 확인 후에만 서버가 보고서 데이터를 내려줍니다 (현재 프로토타입의 잠금은 화면 구성용). 결제는 PG 결제 링크 → 웹훅으로 시작하면 가장 빠릅니다 (`config.js`의 `checkoutUrl`).
- **이의제기 절차**: 판정에 대한 재검토 요청 경로와 처리 기한. 정정 발언이 확인되면 재평가.
- **재평가·만료**: 인증서에 기준일을 명시하고, 월간 모니터링 상품은 정기 재평가 + 등급 변동 알림.
- **투명성**: 평가 방식 페이지 공개 (이 저장소의 `METHODOLOGY.md`가 출발점), 판정마다 기관·문서 표기.
- **약관·고지**: "법적 효력 없음 · 투자 권유 아님 · 알고리즘 평가"를 인증서와 모든 화면에 유지.

## 5. 단계 제안

| 단계 | 목표 | 산출물 |
|---|---|---|
| **0. 수요 검증** (지금) | 랜딩 + 샘플 인증서로 관심도 측정 | 이 프로토타입을 배포, 대기자 명단/사전 신청 수집 |
| **1. 컨시어지 MVP** | 소수 고객의 계정을 반자동(스크립트 + 사람 검수)으로 분석해 실제 인증서 발급 | 수동 파이프라인, 검증 페이지, 결제 링크 |
| **2. 자동화** | 발언 추출·근거 검색·판정 자동화, 검수는 예외 건만 | OAuth 연동, 근거 인덱스, 평가 데이터셋(정답 라벨) |
| **3. 확장** | 월간 모니터링, 기관/미디어용 API, 공인 평가(법률 검토 후) | 구독 결제, 대시보드 |

2단계 전에 **정답 라벨이 붙은 평가 데이터셋**(발언 100~300건 정도)을 만들어 추출·판정 정확도를 측정하세요. 이 서비스의 가치는 점수의 *정확도와 설명 가능성*에 달려 있고, 틀린 판정은 곧 신뢰 문제입니다.
